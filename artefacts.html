Data Cleaning Activity

In weeks 4 - 5 I completed the data cleaning task. This task strengthened my understanding of how structured data preparation influences data quality, consistency, and efficiency. Kazil and Jarmul (2016) provide an example in their book using the UNICEF Zimbabwe survey dataset, which involves converting SPSS files into CSV format, obtaining full variable descriptions through web scraping, and replacing short variable names with meaningful headers to improve the readability of the dataset. I worked through this example to develop a practical understanding of the data cleaning process and applied the techniques demonstrated to the dataset. As part of this process, I developed a systematic approach to checking whether all variables had corresponding headers before removing unmatched fields and aligning the remaining data with their descriptions. Further examination of the dataset helped me understand the importance of identifying data types, missing values, duplicates, inconsistent formatting, and potential errors before conducting analysis (Huxley, 2020). I also used fuzzy matching to identify values that were similar but not identical, allowing potential inconsistencies, such as differences in spelling or formatting, to be flagged for review. Combining these processes into a single script demonstrated how scripting can make data cleaning more structured, repeatable, and efficient (Kazil and Jarmul, 2016). Overall, working through the example provided by Kazil and Jarmul (2016) improved my practical understanding of data cleaning and demonstrated how clearly defined inputs, outputs, data models, and automated transformations can support effective data pipelines and provide a stronger foundation for accurate and scalable data analysis.

    • Normalisation Task

    In week 7 I completed the normalisation task strengthened my understanding of how database structure influences data quality and efficiency. Database normalisation is a systematic process of organising relational data into progressively higher normal forms (1NF, 2NF, and 3NF) to minimise redundancy, prevent update anomalies, and maintain data integrity (Chen, 2023). Working through 1NF, 2NF, and 3NF helped me recognise and resolve redundancy and dependency issues systematically. My normalised task achieved 1NF by ensuring that each cell contained only a single value, achieved 2NF by ensuring that all attributes were fully dependent on the primary key, and achieved 3NF by ensuring that non-key attributes depended on “the key, the whole key, and nothing but the key.” I also reflected on how appropriate data modelling supports scalable solutions, reduces inconsistencies, and provides a stronger foundation for managing complex datasets.

    • Data Building Task

    Also in Week 7, I completed the data building task. The data build task allowed me to apply normalisation principles in a practical database environment. Creating linked tables and implementing primary and foreign keys strengthened my understanding of relational data structures and referential integrity. Testing the database also highlighted the importance of validating relationships to maintain data consistency and support reliable data processing.

    API Security Requirements

    In week 10, I completed the API security requirements task developed my understanding of the risks involved in sharing and accessing data through APIs. Evaluating authentication, authorisation, data protection and potential vulnerabilities helped me recognise that secure data wrangling requires security to be considered alongside functionality. Working collaboratively also reinforced the importance of assessing risks from different perspectives.
