Project Overview

Project Title

AI-Assisted Ultra-Marathon DNF Database Analytics and Dashboard

Project scenario and client

As participation in ultra-distance running continues to grow, race organisers face challenges in understanding why some races have higher levels of non-completion. This project focuses on analysing characteristics associated with runners not completing a race (Did Not Finish - DNF).

For this project, I position myself as a database and data analytics consultant working for a fictional ultra-running organisation. The client is interested in investigating which race characteristics are associated with higher DNF rates across ultra-marathon events.

The organisation requires a structured approach to analysing DNF patterns across races. This could help race organisers identify races with comparatively high levels of non-completion and investigate which characteristics may be associated with these outcomes.

The proposed solution is a relational database capable of storing, cleansing, managing and analysing race data from the UTMB World Race dataset. The resulting analytical data will be presented through an interactive dashboard to provide the client with meaningful insights into DNF patterns.

The project will also investigate how AI tools can support database development and analytics, including database design, data cleansing, SQL development, feature extraction and insight generation. AI-generated outputs will be reviewed and validated by the researcher.

Project Aim

To design and develop an AI-assisted relational database and analytics solution that enables a fictional ultra-running organisation to investigate the characteristics associated with Did Not Finish (DNF) outcomes.

Project Objectives

The objectives of this project are:

  • Identify the data requirements for analysing DNF outcomes.
  • Investigate the quality and structure of the UTMB World Race dataset.
  • Identify race characteristics that can be analysed in relation to DNF.
  • Design and implement a relational database for the race data.
  • Use Python and Pandas to clean and transform the dataset.
  • Develop SQL queries to analyse DNF patterns.
  • Calculate DNF rates and other relevant measures.
  • Investigate associations between race characteristics and DNF.
  • Develop an interactive dashboard to communicate the findings.
  • Evaluate the usefulness and limitations of AI within the project.

Project Research Questions

The key research questions guiding the project are:

  • PQ1: What data entities, attributes and relationships are required to analyse DNF outcomes?
  • PQ2: What data-quality issues exist within the UTMB dataset, and how can they be addressed?
  • PQ3: Which available race characteristics are associated with higher DNF rates?
  • PQ4: How does DNF rate vary between races with different characteristics?
  • PQ5: Can the available race characteristics help identify races with comparatively high DNF rates?
  • PQ6: How useful and accurate are AI-generated database and analytical outputs when validated by the researcher?
Client Requirements

What does the client require?

The client requires a database and analytics system that can store and analyse ultra-marathon race characteristics and DNF information. The system should allow race organisers to compare DNF rates between races and investigate characteristics that may be associated with higher levels of non-completion.

Why does the client need this?

The client needs these insights to better understand patterns in race non-completion. Identifying associations between race characteristics and DNF can provide evidence to support further investigation, race planning and risk assessment.

What decisions should the database support?

The database should support decisions relating to:

  • Identifying races with high DNF rates.
  • Comparing DNF rates between different races.
  • Investigating relationships between race characteristics and DNF.
  • Identifying race characteristics that warrant further investigation.
  • Supporting evidence-based race planning and risk assessment.

Core database tables

As the project uses only the UTMB World Race dataset, the database can be kept relatively simple. There is no requirement for customer, product, purchase, training or recommendation tables.

The database will focus on race information, race characteristics and participation outcomes.

Table 2: Core database tables

Table Purpose
Races Stores information identifying each race and its available characteristics.
Race Outcomes Stores participant, finisher and DNF measures for each race.
